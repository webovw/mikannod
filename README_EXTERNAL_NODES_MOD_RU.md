# Mikan External Nodes MOD

**Это модифицированная сборка Mikan, а не Community Addon.** Она добавляет импорт клиентских Xray JSON outbound-конфигураций в существующую админ-панель и включает импортированные прокси в обычную выдачу подписок.

> Проект основан на исходном коде Mikan. Это сторонняя модификация, неофициальная и не поддерживаемая авторами Mikan. Перед обновлением сделайте резервную копию PostgreSQL и текущего образа.

## Что добавлено

- Новый пункт меню **Внешние ноды** в существующей админ-панели.
- Импорт полного Xray JSON через `outbounds`.
- Извлечение VLESS, VMess, Trojan и Shadowsocks.
- TCP, WebSocket, gRPC, HTTPUpgrade, XHTTP; TLS и REALITY.
- Возможность задать собственное название, включать/выключать сервер и отдельно управлять участием в `Auto`.
- Хранение внешних прокси в отдельной таблице PostgreSQL `external_nodes`.
- Добавление внешних прокси в штатный путь формирования подписок: Xray-клиентам — share URI, mihomo-клиентам — proxy entries.
- Миграция `0053_external_nodes` запускается штатным механизмом миграций Mikan.

## Важно: что это НЕ делает

- Это не устанавливается через **Аддоны → Источники аддонов**. Там устанавливаются Community Addons по протоколу Mikan Addon, а данный проект меняет backend, frontend и генератор подписок Mikan.
- Импортированный сервер — клиентская конфигурация стороннего VPN, а не управляемая Mikan серверная нода. У него нет агента Mikan, серверного inbound и штатного учёта трафика Mikan.
- Для Happ/Xray внешние серверы выдаются как обычные подключения в подписке. Группа `Auto` в формате Xray share URI не переносится: это функция профиля mihomo/Clash. В mihomo-профиле внешние прокси включаются в основной selector и `Auto` согласно переключателю.
- Вставленный JSON — снимок конфигурации. Автоматического получения обновлений от провайдера нет, поскольку импортируется JSON, а не URL подписки. Для обновления вставьте свежий JSON повторно.
- Импортируются поддерживаемые outbound-записи; `inbounds`, DNS, routing, metrics и локальные `freedom`/`blackhole` не переносятся.
- Исходный JSON содержит секреты подключения (UUID, пароли, ключи). Ограничьте доступ к панели и резервным копиям БД.

## Структура изменений

- `internal/panel/externalnodes/` — разбор и преобразование Xray JSON.
- `internal/panel/api/externalnodes.go` — API админ-панели.
- `internal/panel/store/postgres/0053_external_nodes.sql` — миграция PostgreSQL.
- `internal/panel/subs/` — добавление внешних proxy в выдачу подписок.
- `web/src/admin/pages/external-nodes.tsx` — страница управления.
- `web/src/admin/router.tsx`, `web/src/admin/shell.tsx` — маршрут и пункт меню.

## Требования к сборке

Используйте версии Go и Node/pnpm, указанные в исходном репозитории и CI. В текущем `go.mod` указано `go 1.27`; сборка на старом Go может автоматически не пройти.

Обычная сборка Docker из корня репозитория:

```bash
docker buildx build -t mikan:external-nodes .
```

Перед развёртыванием проверьте Dockerfile и конфигурацию именно вашей установки Mikan. Не заменяйте production-контейнер до успешной сборки и проверки на тестовой копии.

## Публикация в GitHub

1. Создайте **свой fork** исходного репозитория Mikan (рекомендуется) либо отдельный репозиторий для этой модификации.
2. Распакуйте содержимое архива так, чтобы `go.mod`, `Dockerfile`, `web/`, `internal/` и `.github/` находились в корне репозитория.
3. Загрузите все файлы в свой GitHub-репозиторий и создайте commit.
4. Для обновлений исходного Mikan сначала сравнивайте изменения upstream и повторно проверяйте модификацию.
5. Для установки собирайте Docker-образ из этого репозитория. Не добавляйте его URL в «Источники аддонов»: это не каталог Community Addons.

Пример публикации через Git:

```bash
git init
git add .
git commit -m "Add external Xray JSON nodes to Mikan"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/mikan-external-nodes-mod.git
git push -u origin main
```

## Проверка перед production

Полная сборка и интеграционные тесты в этой среде не запускались: проект требует Go 1.27 и соответствующую frontend toolchain. Сначала выполните CI/build в GitHub Actions или локально, затем протестируйте импорт на копии панели и проверьте выдачу Happ и mihomo отдельно.
